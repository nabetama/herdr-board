# herdr-board

Herdr で並行して動かしているエージェント（主に Claude Code）を、
「自分を必要としているか / 終わったか / 作業中か / 待機中か」で振り分けて 1 画面に一覧する web UI。

## 起動

```sh
python3 board.py            # http://127.0.0.1:7788/ を開く
python3 board.py --port 8000
python3 board.py --no-pr    # gh で PR を調べない
```

端末版（サーバーは立てない）:

```sh
python3 board.py --tui                 # 3 秒ごとに更新
python3 board.py --tui --interval 5    # 更新間隔を変える
python3 board.py --tui --no-pr
```

- 必要なもの: Python 3.9 以上（標準ライブラリだけ）、`herdr`。PR 表示を使うなら `gh`（ログイン済み）。
- ビルド手順はない。サーバーは `127.0.0.1` にだけ bind する。
- テスト: `python3 -m unittest`

## 画面の見方

上から次のセクションが並ぶ。各セクション内は「その状態になったのが新しい順」。

| セクション | 色 | 意味 |
|---|---|---|
| NEEDS YOU | オレンジ | あなたの操作が要る。行の 2 行目に何を求めているか（`you: approve Bash: ...` など）と理由のラベルを出す |
| DONE · UNSEEN | 緑 | 仕事を終えて、まだ見ていない（Herdr の `done`） |
| WORKING | 青 | 作業中 |
| IDLE | グレー | 待機中 |

各行は左から、状態の色の丸 / エージェント名（Herdr の名前。なければ Claude Code のセッション名）/
タイトルと補足 / バッジ / エージェント種別 / 経過時間。

- **タイトル**: 次の順で最初に見つかったもの。
  1. 会話ログの custom-title（`/rename` などで付けた名前）
  2. Claude Code のセッション名（自動で付いた名前 `nameSource: derived` は除く）
  3. 最初の依頼の 1 行目（`#` や `依頼:` は外す）
  4. 最後のユーザー発言
  5. cwd のディレクトリ名
- **補足（2 行目）**: NEEDS YOU は求めていること。WORKING は直近のツール呼び出し。ほかは最後のアシスタント発言。
- **バッジ**:
  - `bg: 1 shell` … 会話ログ上で、バックグラウンドで起動して完了通知がまだ来ていないタスクの数（shell / monitor / agent など）
  - `repo#123` … 関係する PR。CI の成否（✓ ✗ …）、draft、approved、changes requested を添える。クリックで PR を開く
  - cwd のディレクトリ名（エージェント名と同じなら出さない）
- **経過時間**: 今の状態になってからの時間（`45s` `12m` `5h` `3d`）。
  サーバーが状態の変化を見たらその時刻から数える。起動直後でまだ変化を見ていないときは推定で、
  working はユーザーの最後の発言の時刻、それ以外は会話ログの最後の記録の時刻から数える。
- Herdr のペイン ID は画面に出さない。

### 操作

- `↑` `↓`（`j` `k`）で行を選択、`Enter` でターミナルの該当エージェントへ移る。行のクリックでも移る。
- 3 秒ごとに自動更新する。選択は行（エージェント）で覚えているので、並びが変わっても同じエージェントを選んだまま。
- 移る処理はサーバー側で `herdr agent focus <名前>`（名前がなければペイン）。
  失敗したら `herdr pane get` で tab を調べて `herdr tab focus <tab>`。
  ブラウザから受け付けるのは、サーバーが直近に返した一覧にある行だけ。

## 端末版（`--tui`）

Herdr の横のペイン（幅 80〜120 桁程度）に置いておく使い方を想定している。
一覧の作り方・振り分け・focus の処理はブラウザ版と同じもの（`Board.snapshot()` / `Board.focus()`）を使うので、
同じエージェントは同じセクションに出る。

- 画面: 1 行目に件数 4 種と更新時刻、2 行目に操作ヒント（Enter の直後は移動の結果）。その下に
  `NEEDS YOU` / `DONE / UNSEEN` / `WORKING` / `IDLE` のセクション。各エージェントは 2 行で、
  1 行目が `*`（状態の色）・名前・タイトル・`bg: N shell`・種別・経過時間、
  2 行目が NEEDS YOU なら理由（オレンジの帯）と求めていること、ほかは補足。
- 色: 256 色。オレンジ（NEEDS YOU）・緑（DONE）・青（WORKING）・グレー（IDLE）。
- 幅: 文字列は表示幅で数えて切る（全角は 2 桁）。はみ出した分は末尾を `~` にする。
  幅 90 桁未満ではエージェント種別、100 桁未満では PR を省く。ペインの幅が変わったら描き直す。
- 表示する文字: 端末によって 1 桁にも 2 桁にもなる文字（`…` `→` `●` `①` など）は ASCII に置き換え、
  制御文字やエスケープシーケンスは取り除く（会話ログの中身をそのまま端末に流さない）。
- 操作: `↑` `↓` / `j` `k` で選択（選択行は `>` と背景色）、`Enter` かクリックでそのエージェントへ移る、
  ホイールで選択を上下、`q` か `Ctrl+C` で終了。終了時にカーソル・マウス・代替画面を元に戻す。
- 一覧が空になったとき（`herdr` の失敗など）は選択を変えない。選択中のエージェントが一覧に無くても、
  2 回の更新までは選択を保つ（ブラウザ版も同じ）。

## 判定ルール

判定は `logic.py` の `classify()` 1 か所にまとめてある。入力は Herdr の `agent_status` と、
会話ログ末尾（512KB）の要約。見逃しより誤検知の方がましという方針で、迷うものは NEEDS YOU に寄せる。

上から順に見て、最初に当てはまったものになる。

| 条件 | セクション | 理由ラベル |
|---|---|---|
| `agent_status` が `working` | WORKING | |
| `agent_status` が `blocked`（Herdr が許可ダイアログか質問 UI を認識） | NEEDS YOU | `blocked` |
| 結果が返っていない `AskUserQuestion` がある | NEEDS YOU | `質問 UI` |
| 結果が返っていないツール呼び出しがある（許可ダイアログを Herdr が認識できていない可能性） | NEEDS YOU | `許可待ち?` |
| 最後のアシスタント発言が質問で終わっている（その後にユーザーが発言していない） | NEEDS YOU | `質問で停止` |
| `agent_status` が `unknown`（Herdr が判定できない） | NEEDS YOU | `状態不明` |
| `agent_status` が `done` | DONE · UNSEEN | |
| それ以外（`idle`） | IDLE | |

`blocked` のときの「何を求めているか」は、未完了の `AskUserQuestion` があればその質問文、
未完了のツール呼び出しがあれば `you: approve <ツール名>: <説明>`、
最後の発言が質問ならその文、どれもなければ汎用の文を出す。

「質問で終わっている」は、最後のアシスタント発言からコードブロックを除いた最後の 4 行のどれかが、
次のどれかに当てはまるとき（`logic.QUESTION_PATTERNS`）。

- 行末が `?` `？`
- 「ますか」「ませんか」「でしょうか」「(いい|よい|よろしい)ですか」「どちら」「どれに/を/が」
- 「教えてください」「選んでください」「指示をください」「判断してください」「承認してください」など、返事を求める依頼
- 英語の `Should I` `Do you want` `Would you like` `Let me know` など

「ご確認ください」は完了報告の締めにも使われるので質問として扱わない。

### 使うデータ

- `herdr agent list`: 状態、名前、cwd、Claude Code の sessionId（`agent_session.value`）、tab
- `~/.claude/sessions/<pid>.json`: セッション名
- `~/.claude/projects/<cwd の / と . を - にした名前>/<sessionId>.jsonl`: 会話ログ。
  末尾 512KB だけ読む（タイトル用の最初の依頼だけは先頭 256KB を読んで覚えておく）。
  ファイルの更新時刻とサイズが変わらなければ読み直さない。
- PR: 会話ログに最後に出た `https://github.com/<owner>/<repo>/pull/<n>`、なければ会話ログの `gitBranch`
  （main / master / develop は除く）を `gh pr view` で調べる。別スレッドで呼び、結果は 120 秒キャッシュする。

## 安全のための制限

- `127.0.0.1` にだけ bind する。`Host` ヘッダーが `127.0.0.1` / `localhost` 以外のリクエストは拒否する（DNS rebinding 対策）。
- focus の API は `Content-Type: application/json` と `X-Herdr-Board: 1` ヘッダーを要求する（他サイトのページからは送れない）。
- `herdr` / `gh` は引数の配列で呼び、シェルを通さない。
- エージェントへの入力（`agent prompt` / `send-keys`）やペインを閉じる操作は一切しない。

## 制限・未対応

- バックグラウンドタスクの数は会話ログの末尾 512KB の範囲で数える。それより前に起動したまま動いているタスクは数えない。
- Claude Code 以外のエージェントは会話ログを読まないので、タイトルは端末タイトル、判定は Herdr の状態だけになる。
- 経過時間はサーバーを再起動すると推定値に戻る。
