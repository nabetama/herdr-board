# herdr-board

Herdr で並行して動かしているエージェント（主に Claude Code）を、
「自分を必要としているか / 終わったか / 作業中か / 待機中か」で振り分けて 1 画面に一覧する web UI。

## 起動

```sh
python3 board.py            # http://127.0.0.1:7788/ を開く
python3 board.py --port 8000
python3 board.py --no-pr    # gh で PR を調べない
```

端末版（`--port` を付けなければサーバーは立てない）:

```sh
python3 board.py --tui                 # 3 秒ごとに更新
python3 board.py --tui --interval 5    # 更新間隔を変える
python3 board.py --tui --no-pr
python3 board.py --tui --port 7788     # 同じプロセスでブラウザ版も動かす（http://127.0.0.1:7788/）
```

作業の一覧表（Markdown）を重ねる（ブラウザ版・端末版のどちらでも使える。詳しくは「作業の一覧表（`--tasks`）」）:

```sh
python3 board.py --tasks ~/work/tasks.md
python3 board.py --tui --tasks ~/work/tasks.md --recent-done 10
```

選んだエージェントの詳細に結果ファイル（`<ディレクトリ>/<名前>.md`）を出す（詳しくは「詳細」）:

```sh
python3 board.py --tui --results-dir ~/work/results
HERDR_BOARD_RESULTS_DIR=~/work/results python3 board.py --tui   # 環境変数でも指定できる
```

- 必要なもの: Python 3.9 以上（標準ライブラリだけ）、`herdr`。PR 表示を使うなら `gh`（ログイン済み）。
- ビルド手順はない。サーバーは `127.0.0.1` にだけ bind する。
- テスト: `python3 -m unittest`

## 画面の見方

上から次のセクションが並ぶ。各セクション内は「その状態になったのが新しい順」。

| セクション | 色 | 意味 |
|---|---|---|
| NEEDS YOU | オレンジ | あなたの操作が要る。行の 2 行目に何を求めているか（`you: approve Bash: ...` など）と理由のラベルを出す |
| DONE · UNSEEN | 緑 | 仕事を終えて、まだ見ていない（Herdr の `done`） |
| WORKING | 青 | 作業中 |
| IDLE | グレー | 待機中 |

各行は左から、状態の色の丸 / エージェント名（Herdr の名前。なければ Claude Code のセッション名）/
タイトルと補足 / バッジ / エージェント種別 / 経過時間。

- **タイトル**: 次の順で最初に見つかったもの。
  1. 会話ログの custom-title（`/rename` などで付けた名前）
  2. Claude Code のセッション名（自動で付いた名前 `nameSource: derived` は除く）
  3. 最初の依頼の 1 行目（`#` や `依頼:` は外す）
  4. 最後のユーザー発言
  5. cwd のディレクトリ名
- **補足（2 行目）**: NEEDS YOU は求めていること。WORKING は直近のツール呼び出し。ほかは最後のアシスタント発言。
- **バッジ**:
  - `bg: 1 shell` … 会話ログ上で、バックグラウンドで起動して完了通知がまだ来ていないタスクの数（shell / monitor / agent など）
  - `repo#123` … 関係する PR。CI の成否（✓ ✗ …）、draft、approved、changes requested を添える。クリックで PR を開く
  - cwd のディレクトリ名（エージェント名と同じなら出さない）
- **経過時間**: 今の状態になってからの時間（`45s` `12m` `5h` `3d`）。
  サーバーが状態の変化を見たらその時刻から数える。起動直後でまだ変化を見ていないときは推定で、
  working はユーザーの最後の発言の時刻、それ以外は会話ログの最後の記録の時刻から数える。
- Herdr のペイン ID は画面に出さない。

### 操作

- `↑` `↓`（`j` `k`）で行を選択、`Enter` でターミナルの該当エージェントへ移る。行のクリックでも移る。
- `d` で選択中のエージェントの詳細を開く・閉じる（「詳細」）。ブラウザ版は画面の下に出し、
  開いている間は `J` `K` と `PageDown` `PageUp` で詳細をスクロールする（マウスのスクロールでも動く）。
  ブラウザ版は、ヘッダーの `詳細` ボタンでも開く・閉じる。
- 3 秒ごとに自動更新する。選択は行（エージェント）で覚えているので、並びが変わっても同じエージェントを選んだまま。
- 移る処理はサーバー側で `herdr agent focus <名前>`（名前がなければペイン）。
  失敗したら `herdr pane get` で tab を調べて `herdr tab focus <tab>`。
  ブラウザから受け付けるのは、サーバーが直近に返した一覧にある行だけ。

## 端末版（`--tui`）

Herdr の横のペイン（幅 80〜120 桁程度）に置いておく使い方を想定している。
一覧の作り方・振り分け・focus の処理はブラウザ版と同じもの（`Board.snapshot()` / `Board.focus()`）を使うので、
同じエージェントは同じセクションに出る。

- 画面: 1 行目に件数 4 種と更新時刻、2 行目に操作ヒント（Enter の直後は移動の結果）。その下に
  `NEEDS YOU` / `DONE / UNSEEN` / `WORKING` / `IDLE` のセクション。各エージェントは 2 行で、
  1 行目が `*`（状態の色）・名前・タイトル・`bg: N shell`・種別・経過時間、
  2 行目が NEEDS YOU なら理由（オレンジの帯）と求めていること、ほかは補足。
- 色: 256 色。オレンジ（NEEDS YOU）・緑（DONE）・青（WORKING）・グレー（IDLE）。
- 幅: 文字列は表示幅で数えて切る（全角は 2 桁）。はみ出した分は末尾を `~` にする。
  幅 90 桁未満ではエージェント種別、100 桁未満では PR を省く。ペインの幅が変わったら描き直す。
- 表示する文字: 端末によって 1 桁にも 2 桁にもなる文字（`…` `→` `●` `①` など）は ASCII に置き換え、
  制御文字やエスケープシーケンスは取り除く（会話ログの中身をそのまま端末に流さない）。
- 操作: `↑` `↓` / `j` `k` で選択（選択行は `>` と背景色）、`Enter` かクリックでそのエージェントへ移る、
  ホイールで選択を上下、`q` か `Ctrl+C` で終了。終了時にカーソル・マウス・代替画面を元に戻す。
- 詳細: `d` で開く・閉じる。開いている間は、画面の上半分に一覧、下半分に詳細を出す。
  詳細の 1 行目は `DETAIL <名前>` と表示中の範囲（`12-30/120` の形）で、その下をスクロールする。
  `J` / `K` で 1 行、`PageDown` / `PageUp` で半画面ずつ。ホイールは詳細を開いていても選択の上下のまま。
  - 選択を変えると詳細の先頭に戻る。3 秒ごとの更新では、同じエージェントならスクロール位置を保つ。
  - 一覧は上半分の中で選択行が見えるようにずらす。クリックで移れるのは上半分の一覧の行だけ（詳細の上のクリックは無視する）。
  - 端末の行数が 9 行以下で、一覧と詳細にそれぞれ 4 行を取れないときは、詳細だけを出す（一覧は隠れるが、`j` `k` で選択は変えられる）。
  - 2 行目の操作ヒントは、詳細を開いている間はスクロールのキーに変わる。
- 一覧が空になったとき（`herdr` の失敗など）は選択を変えない。選択中のエージェントが一覧に無くても、
  2 回の更新までは選択を保つ（ブラウザ版も同じ）。
- ブラウザ版も一緒に動かす（`--tui --port N`）: 同じプロセスの別スレッドで、`127.0.0.1:N` にブラウザ版のサーバーを立てる。
  - 一覧（`Board.snapshot()`）は端末版とブラウザ版で共有する。`--interval` から 0.5 秒引いた時間（最短 1 秒）より新しい一覧があればそれを返すので、
    両方から求められても `herdr agent list` や会話ログの読み込みは二重にならない。
  - 起動できたら 2 行目に `web: http://127.0.0.1:N/` を 10 秒出す。ポートが使用中などで起動できないときは、
    端末版だけで動き続け、2 行目に `web: could not open port N (...); terminal only` を出し続ける。
  - `q`・`Ctrl+C`・ペインを閉じる（SIGHUP）・SIGTERM のどれで終えても、サーバーを止めてポートを閉じる。

## 詳細

一覧で選んだエージェントについて、次の 3 つを上から順に、切らずに出す（端末版・ブラウザ版とも `d` で開く）。
対象は Herdr にいるエージェントの行だけ（`RECENT DONE` の行は選択できないので対象外）。

1. 結果ファイル（`RESULT FILE`）: `<ディレクトリ>/<名前>.md` の中身。
   - ディレクトリは `--results-dir` で指定する。無ければ環境変数 `HERDR_BOARD_RESULTS_DIR`。どちらも無ければ、この欄は出さない。
   - `<名前>` はエージェントの Herdr の名前（無ければ表示名）。
   - ファイルが無いときは `(none: the file does not exist)` の 1 行を出す。256KB を超える分は読まず、その旨を 1 行出す。
2. 作業の一覧表の行（`TASK`）: `--tasks` を付けたときだけ出す。
   - 進行中の表に同じ名前の行があれば `依頼内容` `状態` `結果・メモ`。一覧では 200 文字で切っているが、詳細では切らない。
   - 進行中に無ければ、完了の表から探して `依頼内容` `終了` `結果`（同じ名前が複数あれば `終了` の新しい方）。
   - どちらにも無ければ、無いことを 1 行出す。
3. 最後のアシスタント発言の全文（`LAST REPLY`）: 会話ログの末尾 512KB から取る。
   会話ログが無いエージェント（Claude Code 以外など）は、無いことを 1 行出す。

- 端末版は、ほかの表示と同じく表示幅で折り返し、制御文字やエスケープシーケンスを取り除いて出す（行頭の字下げは残す）。
- ブラウザ版は `GET /api/detail?id=<行 id>` で選択中の 1 件だけを取る（3 秒ごとの `/api/board` には全文を載せない）。

## 作業の一覧表（`--tasks`）

エージェントを起動した側が「誰に何を頼んだか」を Markdown の表で管理している場合に、その内容を一覧に重ねる。
`--tasks <path>` を付けたときだけ読む。更新のたびにファイルの更新時刻とサイズを見て、変わっていれば読み直す。
ファイルが無い・読めないときは、画面（端末版は 2 行目、ブラウザ版は一覧の上）とサーバーの標準エラーに警告を 1 行出すだけで、ほかの表示はそのまま続ける。

### 表の形式

レベル 2 の見出し（`## `）で区切り、`進行中` と `完了` の下にある表を読む。ほかの見出しの下の表は読まない。
列は見出し行の名前で探すので、順番や余分な列（ペイン・開始など）は気にしなくてよい。区切り行（`|---|`）はどこにあっても読み飛ばす。
セルの中の `|` は `\|` と書く。`名前` の列が無い表は使わない。

```markdown
## 進行中

| 名前 | 状態 | 依頼内容 | 結果・メモ |
|---|---|---|---|
| docs-writer | 確認待ち | 利用手順の書き直し | 図を入れるか聞いている |
| test-fixer | working | 不安定なテストの修正 | |

## 完了

| 名前 | リポジトリ | 終了 | 依頼内容 | 結果 |
|---|---|---|---|---|
| lint-cleanup | sample-app | 01-02 18:05 | lint の警告を消す | 12 件修正 |
```

| 何を | 受け付ける語（大文字小文字は区別しない） |
|---|---|
| 進行中の見出し | `進行中` `作業中` `In progress` `Active` `Doing` `Running` `Ongoing` |
| 完了の見出し | `完了` `済み` `Done` `Completed` `Finished` `Closed` |
| 名前の列 | `名前` `エージェント` `name` `agent` |
| 状態の列（進行中） | `状態` `ステータス` `status` `state` |
| 依頼内容の列 | `依頼内容` `依頼` `内容` `task` `request` `description` |
| メモの列（進行中） | `結果・メモ` `メモ` `結果` `note` `notes` `memo` `result` |
| リポジトリの列（完了） | `リポジトリ` `repo` `repository` |
| 終了の列（完了） | `終了` `完了日時` `ended` `end` `finished` `done at` `completed` |
| 結果の列（完了） | `結果` `結果・メモ` `result` `results` `note` `notes` |

### 重ね方

- 進行中の表の `名前` が、エージェントの Herdr の名前（無ければ表示名）と一致する行に重ねる。
  - タイトルを表の `依頼内容` にする。
  - 補足（2 行目）を表の `結果・メモ` にする。ただし会話ログから NEEDS YOU と判定されているときは、そちらの「何を求めているか」を残す。メモが空なら今の補足のまま。
- 表の `状態` が次のどれかを含む行は、Herdr の状態にかかわらず NEEDS YOU に入れ、理由ラベルを `表: <状態>`（例: `表: 確認待ち`）にする。
  会話ログからすでに NEEDS YOU と判定されているときは、会話ログ側の理由を残す。
  - `質問待ち` `確認待ち` `判断待ち` `回答待ち` `承認待ち` `needs-you` `needs_you` `needs you` `waiting for user` `question`
- 一覧のいちばん下に `RECENT DONE` として、完了の表から `終了` の新しい順に 5 件（`--recent-done N` で変更）を出す。
  `終了` は数字の並びで比べる（`01-02 18:05` や `2026-01-02 18:05` の形を想定）。同じなら表で下にある行を新しいとみなす。
  これらは Herdr にいないので、選択・移動の対象にしない。
- 表の `ペイン` 列は使わない（ペイン ID は画面に出さない）。

## 判定ルール

判定は `logic.py` の `classify()` 1 か所にまとめてある。入力は Herdr の `agent_status` と、
会話ログ末尾（512KB）の要約。見逃しより誤検知の方がましという方針で、迷うものは NEEDS YOU に寄せる。

上から順に見て、最初に当てはまったものになる。

| 条件 | セクション | 理由ラベル |
|---|---|---|
| `agent_status` が `working` | WORKING | |
| `agent_status` が `blocked`（Herdr が許可ダイアログか質問 UI を認識） | NEEDS YOU | `blocked` |
| 結果が返っていない `AskUserQuestion` がある | NEEDS YOU | `質問 UI` |
| 結果が返っていないツール呼び出しがある（許可ダイアログを Herdr が認識できていない可能性） | NEEDS YOU | `許可待ち?` |
| 最後のアシスタント発言が質問で終わっている（その後にユーザーが発言していない） | NEEDS YOU | `質問で停止` |
| `agent_status` が `unknown`（Herdr が判定できない） | NEEDS YOU | `状態不明` |
| `agent_status` が `done` | DONE · UNSEEN | |
| それ以外（`idle`） | IDLE | |

`blocked` のときの「何を求めているか」は、未完了の `AskUserQuestion` があればその質問文、
未完了のツール呼び出しがあれば `you: approve <ツール名>: <説明>`、
最後の発言が質問ならその文、どれもなければ汎用の文を出す。

「質問で終わっている」は、最後のアシスタント発言からコードブロックを除いた最後の 4 行のどれかが、
次のどれかに当てはまるとき（`logic.QUESTION_PATTERNS`）。

- 行末が `?` `？`
- 「ますか」「ませんか」「でしょうか」「(いい|よい|よろしい)ですか」「どちら」「どれに/を/が」
- 「教えてください」「選んでください」「指示をください」「判断してください」「承認してください」など、返事を求める依頼
- 英語の `Should I` `Do you want` `Would you like` `Let me know` など

「ご確認ください」は完了報告の締めにも使われるので質問として扱わない。

### 使うデータ

- `herdr agent list`: 状態、名前、cwd、Claude Code の sessionId（`agent_session.value`）、tab
- `~/.claude/sessions/<pid>.json`: セッション名
- `~/.claude/projects/<cwd の / と . を - にした名前>/<sessionId>.jsonl`: 会話ログ。
  末尾 512KB だけ読む（タイトル用の最初の依頼だけは先頭 256KB を読んで覚えておく）。
  ファイルの更新時刻とサイズが変わらなければ読み直さない。
- PR: 会話ログに最後に出た `https://github.com/<owner>/<repo>/pull/<n>`、なければ会話ログの `gitBranch`
  （main / master / develop は除く）を `gh pr view` で調べる。別スレッドで呼び、結果は 120 秒キャッシュする。
  URL を拾うのは、アシスタントの発言・ユーザーの発言・`gh pr ...` を実行したコマンドの出力だけ。
  ファイルを読んだ結果などに含まれる URL は、そのエージェントの PR とは限らないので拾わない。

## 安全のための制限

- `127.0.0.1` にだけ bind する。`Host` ヘッダーが `127.0.0.1` / `localhost` 以外のリクエストは拒否する（DNS rebinding 対策）。
- focus の API は `Content-Type: application/json` と `X-Herdr-Board: 1` ヘッダーを要求する（他サイトのページからは送れない）。
- 詳細の API（`/api/detail`）も `X-Herdr-Board: 1` ヘッダーを要求する（結果ファイルや会話ログの中身を、他サイトのページから読めないように）。
  focus と同じく、サーバーが直近に返した一覧にある行だけを受け付ける。
- 結果ファイルとして読むのは、`--results-dir`（または `HERDR_BOARD_RESULTS_DIR`）の直下の `<名前>.md` だけで、先頭 256KB まで。
  名前に `/` や `..` を含むとき、シンボリックリンクなどで解決したパスが指定のディレクトリの外に出るとき、通常のファイルでないときは読まない。
- `herdr` / `gh` は引数の配列で呼び、シェルを通さない。
- エージェントへの入力（`agent prompt` / `send-keys`）やペインを閉じる操作は一切しない。

## 制限・未対応

- バックグラウンドタスクの数は会話ログの末尾 512KB の範囲で数える。それより前に起動したまま動いているタスクは数えない。
- Claude Code 以外のエージェントは会話ログを読まないので、タイトルは端末タイトル、判定は Herdr の状態だけになる。
- 経過時間はサーバーを再起動すると推定値に戻る。
- ブラウザ版で `j` `k` `d` `J` `K` が効かないときは、キーを使うブラウザ拡張（Vimium など）が先に受け取っている。
  拡張はページより先にキーを受け取って止めるので、ページ側からは回避できない。次のどれかで操作する。
  - 拡張の設定で、このページを除外する（Vimium なら「Excluded URLs and keys」に `http://127.0.0.1:7788/*` を足す。キーだけ外すなら `jkdJK` を書く）。
  - 矢印キー（選択）、`Enter`（移る）、ヘッダーの `詳細` ボタン（開閉）、`PageDown` `PageUp` かマウスのスクロール（詳細のスクロール）を使う。
    Vimium は既定ではこれらのキーを使わない。
